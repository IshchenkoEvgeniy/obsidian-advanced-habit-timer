# Advanced Habit Timer & Stats

Плагин для [Obsidian](https://obsidian.md): фокус-таймер и трекер привычек с задачами, проектами, медиа-библиотекой, статистикой, Telegram-ботом и опциональным облачным компаньоном на Cloudflare.

English summary below ↓

## Возможности

- **⏱ Таймер и привычки** — секундомер и Pomodoro, цели по привычкам, музыкальный плеер для фокус-сессий, сохранение и восстановление сессий.
- **✅ Задания** — ежедневное планирование задач, повторяющиеся задачи, реестр выполненных в ежедневных заметках, перенос незавершённых.
- **📋 Проекты** — доска (kanban), таблица, календарь, дашборд и таймлайн; подзадачи, прогресс и быстрые действия.
- **📚 Библиотека** — трекинг медиа (книги, манга и свои коллекции): прогресс, рейтинги, серии, цели на год, темп чтения, таймлайн.
- **📊 Статистика** — тепловые карты за год, стрики, детальная аналитика, геймификация (достижения и уровни).
- **🗂 Рабочая область** — единая навигация между разделами: Сегодня, Таймер, Задания, Проекты, Библиотека, Статистика.
- **💬 Telegram** — бот с живыми уведомлениями таймера, утренним планом и вечерней сводкой, недельным отчётом, управлением таймером из чата и Mini WebApp.
- **☁️ Cloudflare-компаньон** (опционально) — синхронизация задач и библиотеки через Workers + D1, обложки в R2, веб-приложение с авторизацией через Telegram.
- **🗓 Ежедневные заметки** — лог сессий и задач в ваших daily notes.
- **🌐 Интерфейс** — русский и английский, светлая/тёмная темы.

## Команды плагина

- **Focus Library** — открыть главное окно рабочей области (иконка «слои» на ленте).
- **Задания** — открыть раздел задач.
- **Telegram: Sync Cloudflare companion** / **Configure Cloudflare webhook**.
- **Telegram: Send Morning Plan Briefing** / **Send Evening Summary Report**.
- **Update Daily Note Project Log**, **Migrate Media Frontmatter (Legacy to New)**.

## Установка

**Вариант 1 — из релиза (рекомендуется):**

1. Скачайте последний архив со страницы [Releases](https://github.com/IshchenkoEvgeniy/obsidian-advanced-habit-timer/releases) — `obsidian-advanced-habit-timer-<версия>.zip`.
2. Распакуйте его в папку плагинов хранилища: `<хранилище>/.obsidian/plugins/` — внутри появится папка `obsidian-advanced-habit-timer` с файлами `main.js`, `manifest.json`, `styles.css`.
3. Перезапустите Obsidian и включите плагин: Настройки → Сторонние плагины.

**Вариант 2 — через BRAT:**

1. Установите и включите [BRAT](https://github.com/TfTHacker/obsidian42-brat).
2. Выполните команду `BRAT: Add a beta plugin for testing` и введите `IshchenkoEvgeniy/obsidian-advanced-habit-timer`.
3. BRAT будет предлагать обновления при новых релизах.

**Вариант 3 — из исходников:**

```bash
npm install
npm run build
```

Скопируйте `main.js`, `manifest.json`, `styles.css` в `<хранилище>/.obsidian/plugins/obsidian-advanced-habit-timer/` и включите плагин в настройках Obsidian.

Для разработки: `npm run dev` (esbuild в режиме наблюдения), тесты — `npm test`, линт — `npm run lint`.

## Чеклист и GitHub Projects

В настройках плагина в карточке проекта нажмите **«Импортировать чеклист как проект»**, укажите полный путь к Markdown-файлу и нажмите **«Импортировать»**. Плагин создаст копию внутри хранилища Obsidian и отдельный проект с источником «Файл». Исходный файл вне хранилища останется на месте. Таблица показывает заголовки второго уровня как этапы, нумерованные пункты как крупные задачи, а чекбоксы как вложенные шаги. Структурированный чеклист открывается сгруппированным по этапам; крупные задачи по умолчанию свёрнуты, а прогресс прямых подзадач показан отдельными сегментами. Круглый значок меняет отметку шага в Markdown; кнопка **+** при наведении на этап, крупную задачу или шаг добавляет вложенную задачу. Меню **⋯** даёт действия раскрытия, добавления и открытия исходного пункта или связанного GitHub Issue.

Кнопка **GitHub Sync** открывает ввод адреса GitHub Project, токена и необязательного адреса репозитория игры. Для работы с Project токену нужен scope `project`; для создания и изменения Issues нужны права на указанный репозиторий (`repo` для приватного или `public_repo` для публичного при использовании classic PAT). Токен хранится только в памяти открытого окна Projects, а адреса и привязки строк сохраняются в настройках плагина.

Для нумерованного чеклиста требуется **репозиторий игры**: GitHub не поддерживает настоящие Sub-issues у draft items. Без адреса репозитория плагин больше не отправляет структурированный чеклист как плоские draft items. С адресом репозитория он создаёт настоящие Issues для этапов, крупных задач, вложенных групп и шагов, связывает их через GitHub Sub-issues и добавляет в Project. Существующие draft items, созданные плагином, преобразуются в Issues, где это возможно. Закрытие и повторное открытие Issue синхронизируется с отметкой шага в Markdown в обе стороны. Синхронизация ручная и возобновляемая: после каждого Issue связь сохраняется в настройках. Используйте репозиторий игры, а не репозиторий самого Obsidian-плагина.

Для остальных файловых и папочных проектов действует обычная синхронизация. Локальные задачи создаются в GitHub как draft issues; синхронизируются названия, поле Status, архив и редактируемые поля типов text, number, date, single select, multi select и iteration. Новые строки GitHub добавляются в локальный проект; существующие Issues и PR обновляются по месту. При одновременном изменении одного поля с двух сторон оно пропускается; удаление строк между системами не передаётся. Исполнители, связанные PR и прогресс подзадач отображаются после синхронизации как поля только для чтения. Сохранённые виды таблицы остаются локальными для плагина. Синхронизация запускается вручную кнопкой.

### Группы над этапами

Кнопка **«Группы этапов»** в таблице открывает список этапов. Задайте одинаковое название группы для нескольких этапов (например, «Прототип», «Основные механики», «Релиз») и нажмите **«Сохранить группы»**. Над этапами появятся сворачиваемые заголовки с количеством и прогрессом завершения этапов. Назначения хранятся в настройках плагина и используют постоянные ключи этапов структурированного чеклиста.

В меню **«Вид → Над этапами»** можно выбрать локальные группы или поле GitHub: Milestone, Iteration, текстовое поле либо Single select. Значения полей этапов обновляются кнопкой **GitHub Sync**. Этап со своим GitHub Issue использует поле этого Issue; для остальных этапов берётся общее значение задач, если оно совпадает у всех. Разные значения у задач сохраняют этап целиком в группе «Без группы этапов». Ручные локальные группы независимы от полей GitHub. Настройка верхней группировки сохраняется вместе с видом таблицы, а состояние сворачивания — при переключении разделов.

Колонка **«Прогресс подзадач»** восстанавливается при открытии таблицы вместе с другими полями; последние изменения колонок сохраняются при повторном открытии активного вида. Для нового вида структурированного чеклиста прогресс включён по умолчанию.

Ширину колонок можно менять, перетаскивая правую границу заголовка. Размеры сохраняются автоматически отдельно для каждого вида, включая поля GitHub. Двойной щелчок по границе сбрасывает ширину одной колонки; **«Вид → Сбросить ширину колонок»** — всех колонок текущего вида. Можно также выделить границу клавишей Tab и менять ширину стрелками (Shift — больший шаг, Home — сброс).

## Cloudflare-компаньон

Отдельное приложение в [`cloudflare-companion/`](./cloudflare-companion): Workers + D1 + R2, разворачивается через `wrangler`. Подробности в его [README](./cloudflare-companion/README.md).

## Безопасность

Токен Telegram-бота и токен Cloudflare хранятся в `data.json` внутри хранилища — это стандартное место настроек плагинов Obsidian, но учитывайте это при использовании сторонних сервисов синхронизации. Ключи не попадают в репозиторий (`data.json` в `.gitignore`).
