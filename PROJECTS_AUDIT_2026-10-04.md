## Ошибки, подтверждённые выполнением текущего кода

### 1. P1 — сохранение полей уничтожает ссылки и inline-изображения

Код: [пересборка строки задачи](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/projects/engine/mutator.ts:167), [преобразование ссылок в отображаемое название](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/projects/engine/task-identity.ts:70).

Достаточно изменить приоритет, статус или срок задачи чеклиста. Сохранение использует уже очищенное отображаемое название и заново строит всю строку. Адреса обычных ссылок и embeds обратно не записываются.

Вход:

```md
- [ ] Demo ![[Assets/a.png]] [Docs](Guide.md) ^demo
```

После изменения только приоритета название в исходном Markdown становится `Demo !Assets/a.png Docs`. Ссылка на `Guide.md` и embed исчезают. Путь первой картинки может остаться в служебном поле обложки, поэтому потеря вложения иногда визуально маскируется. При нескольких изображениях остальные теряются как ссылки. Физические файлы изображений не удаляются.

Этот дефект остался после предыдущего аудита изображений. Новое добавление картинок в описание его обходит, но не исправляет обычное сохранение существующих inline-вложений.

**Исправление:** сохранять исходное Markdown-название отдельно от отображаемого. При изменении полей сохранять исходные ссылки, embeds и форматирование. Явное переименование задачи должно иметь согласованную политику обработки вложений.

### 2. P1 — перетаскивание карточки повреждает содержимое других задач

Код: [обработчик переноса](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/components/projects/Board.svelte:329).

Обработчик берёт все задачи целевой колонки из `ctx.allTasks`, включая скрытые фильтром задачи и подзадачи, и вызывает полное сохранение каждой. Воспроизведено: перенести карточку B перед A в той же колонке; embed в A удаляется, хотя пользователь менял только B.

Причина потери ссылки общая с пунктом 1, но этот обработчик распространяет её на другие задачи. Он также выполняет лишние записи и увеличивает вероятность частичного выполнения при конфликте версий.

**Исправление:** для чеклиста перемещать исходный Markdown-блок через существующий `moveTaskBefore`; для смены статуса сохранять только переносимую задачу. Для задач в отдельных файлах обновлять порядок только там, где он действительно изменился, учитывая корни и иерархию.

### 3. P1 — чекбокс подзадачи может изменить другую задачу

Код: [запись по номеру строки](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/projects/engine/mutator.ts:54), [вызов с сохранённым номером строки](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/components/projects/Board.svelte:472).

Сценарий: загрузить доску, изменить исходный Markdown так, чтобы прежняя подзадача переместилась или исчезла, затем кликнуть её старый чекбокс до обновления доски. Автообновление по событию metadata cache отложено на 500 мс.

Выполненная проверка: после удаления строки Child её номер заняла задача Other. Вызов `toggleSubtask` со старым номером отметил Other выполненной. Проверка `expected` не предотвращает это: ожидаемый текст читается уже из текущего файла при клике, вместо использования идентичности выбранной подзадачи.

**Исправление:** передавать ID/block ID и ожидаемый исходный текст выбранного пункта. Находить актуальную строку по ID, а при исчезновении или конфликте прекращать операцию с уведомлением.

### 4. P2 — порядок карточек в файловом проекте не сохраняется

Код: [сохранение числового порядка при переносе](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/components/projects/Board.svelte:336), [путь сохранения чеклиста](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/projects/engine/mutator.ts:115).

Воспроизведено на колонке A, B, C: перенос C перед B заканчивается порядком A, B, C. Доска передаёт `order`, однако ветка сохранения чеклиста его не применяет; парсер снова получает порядок из положения строк. В таблице для этого уже используется физическое перемещение Markdown-блока.

**Исправление:** разделить сохранение порядка для файлового чеклиста и задач в отдельных заметках; использовать `moveTaskBefore` для чеклиста.

### 5. P2 — поиск по подзадаче показывает пустую доску

Код: [общий фильтр](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/store/ProjectsStore.ts:25), [исключение детей из карточек](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/components/projects/Board.svelte:107).

Воспроизведено на Parent → Needle. Поиск `Needle` оставляет в `filteredTasks` только ребёнка; доска исключает его по `parentId`. В результате не видны ни совпадение, ни родитель. Аналогичный результат возможен при фильтре по метке или привычке, присутствующей только у ребёнка.

**Исправление:** включать родителей найденных потомков в отображаемые корни и показывать найденные подзадачи внутри соответствующей карточки.

### 6. P2 — переименование статуса меняет примеры кода

Код: [renameStatuses](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/projects/project-data.ts:146).

В отличие от парсера и большинства операций записи, этот путь не использует `markdownContentLines`. При переименовании Backlog → Inbox заменяются `## Backlog` и `<!-- project-status: Backlog -->` внутри блока ` ```md `. Воспроизведено с настоящим методом и mock Vault.

**Исправление:** применять тот же фильтр реальных строк Markdown, который используется парсером, включая fenced code, YAML и HTML-комментарии.

### 7. P2 — закрытие редактора не отменяет загрузку картинки

Код: [асинхронная загрузка](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/projects/modals/task-editor.ts:264), [закрытие окна](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/projects/modals/task-editor.ts:340).

Выполнены текущие обработчики загрузки и закрытия редактора с задержанным `arrayBuffer()`. После закрытия окна и завершения чтения всё равно создаётся `Assets/upload.png`. Задача не сохранялась, ссылка отсутствует в сохранённых заметках. Обычная отмена после уже законченной загрузки тоже оставляет созданный файл.

Ранее найденное сохранение во время уже начатой загрузки теперь блокируется. Отмена и жизненный цикл загрузок остаются не обработаны.

**Исправление:** вести состояние закрытия/черновика, проверять его после асинхронных операций, отслеживать только новые файлы данного редактора и безопасно убирать непривязанные загрузки при отмене.

### 8. P2 — разбор изображений не соответствует обычному Markdown

Код: [extractProjectImageReferences](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/projects/image-utils.ts:35).

Подтверждены два сценария:

- `![a](Assets/a.png "Caption")`: подпись включается в путь, resolver возвращает `null`, существующая картинка не отображается.
- `![[Assets/a.png]]` внутри fenced code или inline code: пример кода считается реальным вложением, может попасть на карточку и стать автоматической обложкой.

Регулярное выражение также заканчивает Markdown destination на первой `)`, поэтому пути со скобками требуют исправления. Порядок смешанных wiki/Markdown embeds и повторная проверка URL после снятия обёртки уже исправлены в прежних изменениях.

**Исправление:** единый разбор с исключением кода, выделением destination и optional title, обработкой скобок и экранирования. Сохранять разницу между буквальными wiki-путями и URL-encoded Markdown-путями.

## Дополнительные проблемы, установленные чтением кода

### 9. P2 — выбранная локальная обложка не обновляется при переименовании изображения

[Выбор обложки](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/projects/modals/task-editor.ts:237) сохраняет голый `file.path`. Для чеклиста путь также попадает в кодированный JSON-маркер. [Обработчик rename](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/main.ts:81) обновляет источники проектов и адреса заметок, но не пути обложек.

Если обложка выбрана без embed в описании, после rename старый путь не разрешается. Наличие отдельной ссылки в описании может дать запасную картинку, но сохранённый выбор обложки остаётся устаревшим. Это ранее отмеченная нерешённая проблема; живое переименование в Obsidian в текущем аудите не выполнялось.

### 10. P2 — ошибки быстрых действий доски не показываются пользователю

[Смена статуса](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/components/projects/Board.svelte:306), изменение срока и перенос вызываются через `void` без `catch`. При отклонении сохранения, например из-за `expectedLine`, пользователь не получает Notice, обновление проекта после ошибки также не выполняется. Перенос меняет `dragged.status` в памяти ещё до успешной записи. В таблице аналогичные действия уже имеют обработку ошибок.

Нужен общий обработчик действий доски с уведомлением, блокировкой повторного запуска и обновлением после частичного выполнения. Оптимистические изменения должны либо подтверждаться записью, либо откатываться.

### 11. P3 — повреждённые русские строки в меню доски

В [подтверждении удаления](L:/Obs/MySecondBrain/.obsidian/plugins/obsidian-habit-timer-main/src/components/projects/Board.svelte:175), суффиксе имени копии и подписи секции подпроектов содержится текст вида `Р В…`. Это содержимое исходника, а не только вывод терминала. Нужно восстановить строки в UTF-8 или вынести их в словарь локализации.

### Почему не проходит штатный набор тестов

- Два падения `cloudflare-project-service.test.ts`: stub `saveTask` возвращает `undefined`, хотя актуальный контракт возвращает `{ file, blockId? }`. Это дефект тестового mock; реальные методы возвращают результат. Не считаю эти падения доказательством сбоя Companion при сохранении.
- Одно падение `parser.test.ts`: тест ждёт Reading для строки `🏷️ Reading [[Habits/Sleep]]`; текущая логика отдаёт приоритет явной ссылке и возвращает Sleep. Нужно согласовать ожидаемый приоритет и обновить тест либо реализацию.
- Четыре проверки рендера таблицы не запускаются: в `tests/__mocks__/obsidian.ts` отсутствуют `FuzzySuggestModal`, `Menu`, `normalizePath`, `parseYaml`, `stringifyYaml`.

### Companion и lint

В `cloudflare-companion/src/pepehub-metadata-api.ts:3–4` импорты заканчиваются на `.ts`, а действующий tsconfig не разрешает `allowImportingTsExtensions`. Отдельная проверка TypeScript Companion не проходит. Это не доказательство ошибки развёрнутого сервера или невозможности сборки Wrangler.

Сообщения ESLint главным образом относятся к типам `any`, проверкам JSON, строкам интерфейса и путям конфигурации. Они требуют разбора, но не равнозначны 86 подтверждённым ошибкам выполнения.

## Состояние недавнего исправления прокрутки

Доска теперь использует range-контрол, напрямую управляющий `boardViewport.scrollLeft`, а измерение выполняется через requestAnimationFrame и ResizeObserver. Прежняя зависимость от ширины скрытого второго scroll-container удалена; при уничтожении компонента снимаются observer, listener и отложенный кадр.

Сборка и Svelte-проверка этого кода проходят. Переключение доска → таблица → доска, изменение ширины окна и сворачивание колонок нужно отдельно проверить в работающем Obsidian: выполнение обработчика в mock не подтверждает реальные размеры и отрисовку Chromium.
