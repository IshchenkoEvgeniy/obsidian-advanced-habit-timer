# Мобильная доска: новая раскладка, аудит и сравнение

## Результат

Мобильная доска получила отдельный полноэкранный режим. Кнопка с раскрывающимися углами справа от названия выводит тот же редактор поверх интерфейса Obsidian. Обратная кнопка возвращает редактор в его окно. Доска не перемонтируется при переключении: выделение, история и текущий текст сохраняются.

Полноэкранный режим не включается автоматически после запуска. При закрытии представления редактор удаляется вместе с обработчиками. При переходе в хаб режим выключается; при переходе во вложенную доску сохраняется.

## Мобильный интерфейс

- Раскладка определяется шириной окна доски и наличием сенсорного указателя. Узкая панель на большом мониторе и телефон в альбомной ориентации также используют компактный интерфейс.
- При открытой доске скрыта общая шапка «Дизайн мира» с кнопками создания. Название, назад и полноэкранный режим помещаются в строку высотой 44 px; инструменты просмотра — в строку 46 px.
- Поиск появляется по кнопке. Сетка, привязка, корзина, экспорт и остальные настройки находятся в меню доски.
- Нижняя панель содержит выбор, руку, заметку, Board и «Ещё». «Ещё» открывает прокручиваемую сетку всех инструментов с поиском. После выбора панель закрывается.
- Выделение карточки не открывает свойства автоматически. Свойства открываются отдельной кнопкой; панель закрывается крестиком и не уменьшает размеры холста.
- Неразобранное и корзина открываются снизу. Нажатие на объект в неразобранном размещает его и закрывает панель.
- Пустой холст перемещается одним пальцем, масштабируется двумя. После отпускания одного пальца второй продолжает перемещение. Для нескольких объектов есть отдельная кнопка выделения.
- Заметка и текст создаются одним нажатием; новый текст пустой, без сохраняемого слова-заглушки. Редактор приближает карточку до читаемого масштаба.
- Размер полноэкранного редактора следует за `visualViewport`, включая появление клавиатуры. При уменьшении рабочей области редактируемый текст снова располагается в видимой части холста. Есть кнопка «Готово».
- Размеры кнопок панелей заданы явно, чтобы крупные кнопки темы Obsidian не растягивали строки на телефоне. Карточки сохраняют собственное форматирование.

## Исправления ошибок

| Ошибка | Исправление |
| --- | --- |
| Меню и слой подписей линий перекрывали закрытие редактора записи и другие панели | Холст получил собственный контекст слоёв; меню использует ограниченный уровень поверх холста и ниже панели записи. Проверено настоящими событиями касания. |
| Новое содержимое карточки могло удалиться после завершения начатого ранее переноса | После сохранения получателя сверяется снимок переносимых объектов и их внутренних связей. При изменении источника новая версия остаётся в исходной доске, а пользователю показывается уведомление. В получателе остаётся уже сохранённая прежняя копия. |
| Отмена первого нажатия ластиком оставляла удалённый штрих и запись в корзине | `pointercancel` восстанавливает рисунок и состояние корзины даже без промежуточного движения. |
| Панорамирование могло при отмене вернуть устаревшее содержимое всей доски | Отмена панорамирования восстанавливает только положение и масштаб, сохраняя изменения содержимого. |
| Импорт изображения мог бесконечно ждать событие загрузки | Общая загрузка размеров ограничена пятью секундами; обработчики и таймер очищаются. Ошибка загрузки даёт резервные размеры. |
| Завершившаяся загрузка могла менять уже закрытый редактор | Изменения после завершения асинхронных операций проверяют, что компонент ещё открыт. Обработчики отключаются до сохранения при закрытии представления. |
| Кнопка «Ещё» могла терять касание | Используется обработка нажатия и отпускания, аналогичная инструментам. Неизменившиеся иконки не пересоздаются при обновлении интерфейса. |
| Вставка URL из буфера ОС создавала текст вместо карточки ссылки | Обычная вставка и кнопка вставки используют одинаковое распознавание URL и загрузку превью. |

## Оптимизация

Перемещения камеры и изменения содержимого имеют отдельные сигналы обновления. Панорамирование и масштабирование не пересобирают описания внешнего вида карточек, списки членов колонок и границы миникарты. Начало обычного перемещения холста не копирует всю доску.

Удаление в корзину копирует только удалённые объекты и связи. Проверка каждого набора в корзине не проверяет заново все живые карточки. Копирование выделения не копирует целиком исходную доску с её корзиной; расчёт новых слоёв и поиск скопированных ID больше не повторяются для каждого объекта по всему массиву.

На последнем общем прогоне Chrome: 500 объектов с отсечением невидимых — около 60 FPS, смонтировано 49; 500 одновременно видимых карточек — около 58 FPS. При параллельной сборке и других браузерных прогонах частота ниже. Эти измерения не оценивают скорость физического телефона.

## Сравнение с другими досками

Сравнение текущего кода с официальной справкой продуктов на 10 октября 2026. Это список оставшихся возможностей, а не обещание полной совместимости.

| Продукт | Чего пока нет в нашей доске | Приоритет для личной базы мира |
| --- | --- | --- |
| Milanote | [Web Clipper](https://help.milanote.com/en/articles/1015930-milanote-web-clipper-for-chrome) для сбора фрагментов веб-страниц; [синхронизированные обычные заметки](https://help.milanote.com/en/articles/5147264-synced-notes) на нескольких досках. Общие записи сущностей у нас уже синхронизируются, обычные стикеры — независимые копии. | Высокий: быстрый сбор референсов и повторное использование текста. |
| Miro | [Лассо и захват бумажных стикеров](https://help.miro.com/hc/en-us/articles/360017572834-Mobile-app); [библиотеки специальных фигур, скрываемые слои и расширенная работа с диаграммами](https://help.miro.com/hc/en-us/articles/4403634496402-Miro-for-mapping-diagramming). Текущий порядок объектов по глубине не заменяет скрываемые тематические слои. | Средний: лассо и слои полезнее облачных командных инструментов для одного пользователя. |
| Excalidraw | [Библиотека повторно используемых компонентов](https://github.com/excalidraw/excalidraw-libraries/blob/main/README.md), добавление собственных групп объектов в библиотеку и обмен такими наборами. У нас есть шаблоны целых досок и два готовых макета, но нет библиотеки отдельных компонентов. | Высокий: можно хранить заготовки локаций, персонажей и механик. |
| Obsidian Canvas | [Полные Markdown-заметки и интерактивные веб-страницы внутри карточек](https://obsidian.md/help/plugins/canvas). Наши сущности показывают выбранные поля; прочий Markdown-файл открывается как вложение. Нет импорта/экспорта редактируемого `.canvas`, используется собственный `.board.json`. | Высокий: полноценные заметки и переносимость данных. |

Отдельно отсутствуют совместное редактирование в реальном времени, комментарии для команды, публикация по ссылке и AI-инструменты уровня Miro. Обычная синхронизация файла хранилищем не даёт совместного редактирования. Эти функции менее важны для текущего сценария одного пользователя.

Моя рекомендация для следующего этапа: полнотекстовые Markdown-карточки, библиотека собственных компонентов, затем синхронизированные стикеры и удобный приём веб-референсов. Большой следующий шаг для мобильного режима — проверка на физическом устройстве с вашей темой и клавиатурой.
