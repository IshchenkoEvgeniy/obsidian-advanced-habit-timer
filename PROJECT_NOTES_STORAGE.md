# Заметки проектов из чеклиста

## Структура

- `Проект.md` — исходный чеклист, заголовки этапов и короткие задачи.
- `Проект.tasks.json` — состояние задач: стабильные ID, родители, статусы, даты завершения, параметры, связи с GitHub и адреса разделов заметок.
- `Проект.tasks.md` — автоматически обновляемый общий список, даты завершения и ссылки `[[заметка этапа#^идентификатор|Заметка]]`.
- `Проект.tasks/` — одна общая заметка на каждый этап. Задачи без этапа используют общую заметку «Задачи без этапа».

Название файла этапа содержит короткий суффикс ID, чтобы одинаковые названия не сталкивались. Заметку этапа можно переименовать через Obsidian: плагин обновляет её адрес в состоянии и общем списке.

## Описания

Каждый этап, задача и подзадача имеют отдельный раздел в общей заметке. Заголовки повторяют иерархию и порядок чеклиста. Рядом со статусом указаны даты, приоритет и другие основные параметры. Полное состояние хранится в JSON.

Описание можно редактировать в редакторе задачи или прямо под её заголовком в заметке. В режиме исходного текста видны служебные HTML-комментарии; их нужно сохранять. Заголовок, статус и даты внутри служебного блока обновляет плагин. Общий текст вне разделов сохраняется, но не является описанием GitHub Issue.

GitHub получает только описание соответствующего раздела, без статусов, служебных комментариев и описаний дочерних задач. При переносе задачи в другой этап её раздел переносится в заметку нового этапа. ID раздела остаётся прежним.

В прежней заметке остаётся блок с тем же якорем и ссылкой на новое место. Старые внешние ссылки продолжают открывать этот блок. Если исходный текст изменили во время переноса, очистка откладывается и обе версии сохраняются.

Редактор и GitHub передают ожидаемое прежнее описание. Если его уже изменили, сохранение останавливается с конфликтом: нужно обновить проект и сравнить тексты. Это защита отдельных записей; изменения исходного чеклиста и нескольких заметок не образуют общую транзакцию.

Дата завершения сохраняется в состоянии, исходной метаинформации задачи, общем списке и разделе заметки. Для задач, завершённых до появления учёта времени, точная дата не выдумывается.

## Перенос прежних заметок

При следующем открытии проекта плагин переносит описания в общие заметки и обновляет ссылки. После сохранения заметок, состояния и общего списка старые отдельные заметки перемещаются в `Проект.tasks/_legacy/`. Они сохраняют полный исходный текст и свойства. Автоматическое обновление внешних wikilinks при переименовании зависит от настройки Obsidian.

При открытии проекта старые checkbox-строки получают сохранённый ID и block ID, а этапы и нумерованные группы — скрытый `project-node`. Прежние ключи сохраняются для совместимости с описаниями и GitHub. После этого переименование и перемещение строк сохраняют их идентичность. Служебные ID нельзя копировать вместе с задачей: дубли останавливают согласование. Ранее утраченные связи автоматически не угадываются.

Если старую заметку изменили во время переноса, её изменённый текст не удаляется: архивирование откладывается. Если раздел повреждён или общая заметка пропала, сохранение и синхронизация останавливаются с ошибкой вместо перезаписи описаний пустым текстом.

Описание удалённой задачи сохраняется в конце прежней заметки как история. Оно перестаёт участвовать в активном списке и синхронизации.

Эта схема применяется к проектам из одного Markdown-чеклиста. Проекты, собирающие отдельные заметки по папке, тегу или запросу, сохраняют существующую структуру.
