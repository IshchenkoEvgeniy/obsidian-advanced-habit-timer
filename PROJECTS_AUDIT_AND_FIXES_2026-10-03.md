# Повторный анализ и исправления Projects — 2026-10-03

Проверены текущие исходники, включая предыдущие незакоммиченные изменения. Найденные ниже сценарии исправлены в коде. Причины установлены чтением исходников; воспроизведение на пользовательском хранилище не выполнялось.

## Идентичность и описания

1. **[P1] Подмена сохранённого ID.** Восстановление по названию/номеру применялось и к строкам, у которых уже был собственный ID. Новая задача с названием прежней могла получить её привязку; нумерованная группа могла подмениться при изменении номера. Теперь устойчивый ID имеет приоритет, сопоставление по тексту применяется только при миграции старых строк. Позиционная подстановка адреса заметки также отключена для строк с сохранённым ID.
2. **[P1] Повтор переноса после прерывания.** Если новая заметка уже получила раздел, а затем пользователь изменил его до повторной попытки, повторный перенос мог заменить новый текст прежней версией. Различающиеся тексты в месте назначения теперь вызывают конфликт и сохраняются для сравнения.
3. **[P2] Поздняя проверка описания.** Служебные маркеры в описании могли обнаружиться после создания задачи или записи других корней. Проверка выполняется до создания/редактирования и до обновления общих заметок. В названия нельзя вставлять метаинформацию скопированной строки задачи. При редактировании описание дополнительно проверяется перед изменением полей; проверка ожидаемой версии непосредственно при записи также сохранена.
4. **[P2] Изменённый текст отдельной заметки при удалении.** Снимок теперь содержит исходное содержимое файла. Удаление отклоняется, если заметка изменилась после загрузки; подпись Companion учитывает обычный текст, а не только описание в специальном блоке.

## Разбор Markdown и создание

5. **[P1] Примеры кода становились задачами.** Checkbox-строки и заголовки внутри fenced code, YAML и HTML-комментариев попадали в структуру проекта и могли получить служебные ID. Добавлен общий фильтр строк Markdown для парсера, поиска задач, этапов, миграции ID, создания, GitHub-импорта и путей Companion.
6. **[P2] Табуляции меняли вложенность.** Часть кода считала табуляцию одним символом, а границы блоков — несколькими пробелами. Теперь используется единая ширина отступа с шагом табуляции в четыре колонки. Вставка подзадач сохраняет вложенность; обычный абзац вне блока завершает прежнюю цепочку родителей. Примеры кода также исключены из вычисления очередного номера подзадачи.
7. **[P2] Пояснение переходило новой задаче.** В обычном чеклисте со статусными заголовками и в отдельной заметке через Companion новая задача могла вставляться перед пояснением последнего пункта. Вставка перенесена за полный Markdown-блок.
8. **[P2] Проект из корня хранилища пустовал.** Папка `/` давала пустой префикс, однако фильтр искал пути, начинающиеся с `/`. Исправлены выбор файлов и вычисление дочерней папки; нормализация папки согласована для создания и редактирования.
9. **[P2] Ссылки `#123` терялись из названия.** Числовые ссылки на Issues распознавались как метки и удалялись из отображаемого названия. Теперь они остаются частью названия. Поле меток проверяется отдельно.

## Таблица, массовые действия и Companion

10. **[P2] Родитель и ребёнок удалялись повторно.** При массовом выборе удаление родителя уже удаляло поддерево; следующая операция для выбранного ребёнка завершалась ошибкой. Диапазоны проверяются и объединяются до одной атомарной записи чеклиста. После ошибки массового действия выбор очищается, проект обновляется, ошибка показывается пользователю. Удаление нескольких отдельных файлов остаётся последовательным.
11. **[P2] Архив оставлял подзадачи в активной таблице.** Дочерние задачи наследуют скрытие архивированного родителя. Архив показывает верхнюю архивированную задачу; восстановление родителя возвращает детей, сохраняя их собственные отметки архива.
12. **[P2] Обычная вложенность не считалась иерархией.** Таблица учитывала этапы и нумерованные группы, но не обычные checkbox-подзадачи. Теперь такая вложенность также ограничивает сортировку. Задачи без этапа группируются по статусу корня, дети не расходятся по разным статусным группам; счётчики и разделение по статусу учитывают корни.
13. **[P2] Частичная запись из Companion.** Подзадачи менялись до проверки новых полей родителя. Поля и названия дочерних задач проверяются заранее. Удаление подзадачи отклоняется, если изменились потомки; запись проверяет актуальность исходного поддерева.
14. **[P2] Вторичная ошибка выглядела как неудавшееся сохранение.** Ошибка обновления дневной заметки возникала после успешного изменения/удаления задачи. Теперь она журналируется отдельно и не выдаёт выполненную основную операцию за неудачу.
